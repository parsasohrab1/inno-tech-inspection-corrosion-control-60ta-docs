# ماژول‌های مهندسی پیشرفته و اتصالات — فرضیات و محدودیت‌ها

> همه این ماژول‌ها **غربالگری/پارامتریک و غیرگواهی‌شده** هستند و خروجی آن‌ها پیش از هر تصمیم عملیاتی باید توسط مهندس صلاحیت‌دار تأیید شود.

## ۱. RBI کمّی (الهام‌گرفته از API 581) — `services/rbi581.py`
- **ساختار** مطابق API 581: `Pf = gff × Df × FMS` ، `Art = max(1 − (t_rd − Cr·age)/(t_min + CA), 0)` ، دسته‌بندی Pf از Df، دسته‌بندی پیامد A–E از مساحت، ماتریس ریسک ۵×۵، ریسک مالی `Pf × CoF`.
- **آنچه رسمی نیست:** جداول API 581 (فراوانی عمومی خرابی، Df، پیامد) دارای مجوز هستند و در دسترس من نبودند؛ مقادیر پیش‌فرض **نماینده/پارامتریک** هستند. جداول رسمی را در `data/config/rbi581_tables.json` قرار دهید تا جایگزین شوند.
- اثربخشی بازرسی (A–E) از روش ۳ بازرسی اخیر تقریب زده می‌شود (PAUT/ToFD→B، UT/RT→C، سایر→E).
- فقط مکانیزم **thinning** پیاده شده (نه SCC، HIC، خزش، CUI در Df).
- همبستگی رتبه‌ی RBI کمّی با ریسک نیمه‌کمّی سامانه روی داده مصنوعی ≈ ۰٫۱۷ است (Spearman)، چون ریسک مالی تحت تأثیر شدید پیامد (مساحت × هزینه) است؛ این انتظار می‌رود دو روش رتبه‌های متفاوتی بدهند و باید با RBI موجود واحد مقایسه شود.

## ۲. IOW (API 584) — `services/iow.py`
- سه سطح حد: **Critical / Standard / Informational** برای هر متغیر هر تجهیز؛ پیش‌فرض‌ها از دما/فشار طراحی و سیال (کلرید، pH، H2S، اکسیژن، ...) ساخته می‌شوند و **نمونه‌اند** (باید توسط مهندس خوردگی تعیین شوند: `PUT /api/iow/{id}/limits`).
- ارزیابی روی ۳۰ روز اخیر؛ هشدار (alert با kind=iow) و **ضریب شتاب خوردگی رو‌به‌جلو** (تا ۳×) از تداوم عبور از حدود که در ارزیابی ریسک اعمال می‌شود.
- داده فرایندی نمایشی **مصنوعی** است (source=synthetic).

## ۳. FFS و CUI — `services/ffs.py`
- **FFS:** تلفات عمومی (Part 4 سطح ۱) و عیب موضعی (Part 5): `λ = 1.285·s/√(D·t_c)`، `M_t = √(1+0.48λ²)`، `RSF = R_t/(1 − (1−R_t)/M_t)`، پذیرش `RSF ≥ 0.9`، `MAWP_r = MAWP·RSF/0.9`، عمر باقیمانده عیب. طول عیب `s` و قطر باید از بازرسی واقعی ارائه شوند؛ در غیر این صورت مقدار محافظه‌کارانه فرض و در خروجی **assumptions** ذکر می‌شود. pitting، تغییر شکل، ترک (Part 9) پوشش داده نشده است.
- **CUI:** امتیاز ۰–۱۰۰ از دمای کاری، نوع عایق، وضعیت پوشش، اقلیم و سن؛ تفکیک CUI فولاد کربنی / ESCC زنگ‌نزن. جایگزین برنامه رسمی CUI (API 583) نیست.

## ۴. اتصال به CMMS / ERP / DCS — `services/integrations.py`
| نوع | جهت | وضعیت آزمون |
|---|---|---|
| `rest_pull` (SAP OData، Maximo REST و ...) | ورودی | تست با سرور ساختگی |
| `sql_pull`، `csv_file` | ورودی | تست با SQLite/فایل |
| `pi_webapi` (OSIsoft/AVEVA PI) | ورودی | تست با سرور ساختگی |
| `opcua` | ورودی | **تست نشده** (نیازمند `pip install asyncua`) |
| `readings_rest` و Push (`/api/integrations/process-data`) | ورودی | تست شده |
| `cmms_rest` (maximo / sap_pm / generic) | خروجی (دستور کار) | تست با سرور ساختگی؛ نگاشت فیلد SAP/Maximo باید با مشاور همان سامانه تأیید شود |
| `csv_export` | خروجی | تست شده |

امنیت: فقط http(s)، مسدودسازی آدرس‌های link-local/metadata (SSRF)، فهرست مجاز میزبان با `INTEGRATION_ALLOWED_HOSTS`، **اسرار فقط از متغیر محیطی** (`auth_env`) و هرگز در پایگاه داده/لاگ؛ مسیر Push با `X-API-Key` (`INTEGRATION_API_KEY`)؛ ایجاد اتصال فقط برای مدیر سیستم؛ همه اقدامات در Audit Trail.
